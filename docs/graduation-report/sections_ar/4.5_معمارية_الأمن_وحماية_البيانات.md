# 4.5 معمارية الأمن وحماية البيانات (Security Architecture)

نظراً لحساسية المعلومات الصحية، تم بناء منصة **NHR Syria** وفق مبدأ "الأمن أولاً" (Security by Design)، حيث تم دمج طبقات حماية متعددة لضمان سرية وسلامة البيانات.

### 1. معمارية المصادقة (Authentication Architecture)
*   **تدفق JWT:** نستخدم توكنات JSON Web Tokens لإدارة الجلسات. عند تسجيل الدخول، يحصل المستخدم على توكن موقع رقمياً يحتوي على هويته ودوره، ويتم إرساله مع كل طلب API للتحقق من هويته.
*   **دورة حياة الجلسة:** يتم ضبط مدة صلاحية التوكنات لضمان عدم بقاء الحسابات مفتوحة لفترات طويلة غير آمنة، مع إمكانية إنهاء الجلسات فوراً عند الضرورة.

### 2. نموذج التفويض (Authorization Model)
*   **مصفوفة RBAC:** يعتمد النظام على التحكم في الوصول المستند إلى الأدوار (Role-Based Access Control). يتم تعريف الصلاحيات بشكل صارم:
    *   **المواطن:** يصل فقط لسجله الشخصي ومواعيده.
    *   **الطبيب:** يصل لسجلات المرضى الذين يقوم بالكشف عليهم ولأدوات العيادة.
    *   **الصيدلاني:** يصل فقط للوصفات الطبية المرتبطة بالرقم الوطني الذي يبحث عنه.
*   **المسارات المحمية:** يتم تطبيق طبقة وسيطة (Middleware) في الـ Backend للتحقق من صلاحية المستخدم قبل تنفيذ أي عملية برمجية أو استعلام عن البيانات.

### 3. حماية البيانات (Data Protection)
*   **تشفير البيانات الحساسة:** يتم تشفير كلمات المرور باستخدام خوارزمية **Bcrypt** القوية، مما يضمن استحالة استرجاعها حتى في حال الوصول لقاعدة البيانات.
*   **النقل الآمن:** فرض استخدام بروتوكول **TLS/SSL** لكافة الاتصالات، مما يمنع هجمات "الرجل في المنتصف" (Man-in-the-Middle) ويضمن تشفير البيانات أثناء انتقالها عبر الإنترنت.
*   **سلامة البيانات:** استخدام القيود البرمجية في Prisma لضمان عدم حدوث تلاعب في السجلات التاريخية أو حذف غير مصرح به للمعلومات الطبية.

### 4. اعتبارات الخصوصية
تم تصميم النظام ليحترم خصوصية المريض، حيث يتم تسجيل "سجل الوصول" (Audit Log) لكل عملية استعلام عن سجل طبي، مما يضمن القدرة على مراجعة من اطلع على بيانات المريض ومتى، وهو متطلب أساسي في المعايير الصحية العالمية.
