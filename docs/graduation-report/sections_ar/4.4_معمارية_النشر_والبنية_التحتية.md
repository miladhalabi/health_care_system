# 4.4 معمارية النشر والبنية التحتية (Deployment Architecture)

تتطلب المنصات الصحية الوطنية بنية تحتية مرنة وموثوقة لضمان استمرارية الخدمة. تم تصميم معمارية النشر في **NHR Syria** لتكون موزعة وقابلة للتوسع.

### 1. تصميم البنية التحتية (Infrastructure Design)
تتكون البيئة التشغيلية للنظام من المكونات التالية:
*   **عميل الويب التقدمي (Frontend PWA):** يتم نشره كـ Static Assets يمكن تقديمها عبر خوادم سريعة أو شبكات توصيل المحتوى (CDN).
*   **خادم واجهة البرمجة (Backend API Server):** يعمل ببيئة **Node.js** ويتعامل مع طلبات REST والمنطق البرمجي.
*   **قاعدة البيانات (PostgreSQL):** تعمل كخادم مستقل لضمان أمن وتكامل البيانات وسهولة إجراء النسخ الاحتياطي.
*   **بوابة التزامن (Socket.io Gateway):** تعمل بالتوازي مع الـ API لإدارة اتصالات الـ WebSockets المفتوحة.

### 2. معمارية تطبيق الويب التقدمي (PWA Architecture)
لضمان عمل النظام في ظروف الشبكة المتغيرة، تم تبني الخصائص التالية:
*   **دعم العمل بدون اتصال (Offline Support):** بفضل الـ **Service Workers**، يمكن للمتصفح تخزين ملفات النظام الأساسية، مما يسمح بفتح التطبيق حتى في حال انقطاع الإنترنت.
*   **استراتيجية التخزين المؤقت (Caching Strategy):** نستخدم استراتيجية "Stale-While-Revalidate" لضمان سرعة ظهور البيانات مع تحديثها في الخلفية فور توفر الاتصال.
*   **بيان التطبيق (Manifest File):** يسمح للمستخدمين بتثبيت المنصة على هواتفهم أو حواسيبهم كأنه تطبيق أصلي، مما يسهل الوصول السريع للخدمة.

### 3. معمارية التوصيل (Reverse Proxy)
يُنصح باستخدام خادم **Nginx** كوكيل عكسي (Reverse Proxy) أمام التطبيق للقيام بمهام:
*   إدارة شهادات التشفير (SSL/TLS).
*   موازنة الحمل (Load Balancing) في حال تعدد مثيلات الخادم.
*   تحسين أداء تقديم الملفات الساكنة وضغط البيانات.

تضمن هذه المعمارية أن يظل النظام متاحاً وسريعاً، مع القدرة على الانتقال من مرحلة النموذج الأولي إلى النشر الوطني واسع النطاق بسهولة.
