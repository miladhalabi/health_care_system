# 5.5 تدفق التزامن في الوقت الفعلي (Real-Time Synchronization Flow)

يعد التزامن الفوري "القلب النابض" لمنصة **NHR Syria**، حيث يضمن ترابط البوابات الثلاث ببعضها البعض دون أي تأخير ملحوظ. يعتمد هذا التدفق على تقنية **WebSockets** عبر مكتبة **Socket.io**.

### 1. أحداث المقبس (Socket Events)
تم تعريف مجموعة من الأحداث (Events) التي تحرك النظام:
*   `join_clinic`: حدث يتم تفعيله عند فتح بوابة العيادة أو المريض لصفحة عيادة محددة، ليتم ضمه إلى "غرفة" (Room) خاصة بتلك العيادة.
*   `queue_update`: يتم بثه عند دخول مريض للطبيب أو خروجه، لتحديث أرقام الانتظار.
*   `new_prescription`: يتم بثه لتنبيه بوابة المريض والصيدلية بصدور وصفة جديدة.

### 2. آلية بث الأحداث (Event Broadcasting)
عند وقوع تغيير في قاعدة البيانات (مثلاً: الطبيب ضغط على "المريض التالي"):
1.  يرسل الـ Frontend طلباً للـ API لتحديث الحالة.
2.  بعد نجاح التحديث في قاعدة البيانات (PostgreSQL)، يطلق الخادم إشارة بث (Broadcast) حصرياً للغرفة المرتبطة بالعيادة المعنية.
3.  يستقبل كافة المستخدمين الموجودين في تلك الغرفة (المرضى في صالة الانتظار، الممرض في الاستقبال) البيانات الجديدة فوراً.

### 3. مزامنة الطوابير (Queue Synchronization)
تتم مزامنة الطوابير بطريقة تضمن الاتساق:
*   يحتوي الحدث المرسل على القائمة المحدثة بالكامل أو كائن يحدد التغيير بدقة.
*   تقوم واجهات المستخدم بإعادة ترتيب القائمة ديناميكياً، مما يلغي الحاجة لطلب البيانات يدوياً مرة أخرى من الـ API (ما يقلل استهلاك البيانات).

### 4. التحديثات الحية للتنبيهات
بالإضافة للطوابير، يتم استخدام التزامن لإرسال إشعارات فورية:
*   عند إصدار وصفة طبية، يتلقى الصيدلاني (إذا كان يبحث عن هذا المريض) إشارة بتحديث قائمة الوصفات المتاحة للصرف.
*   يتحول لون أيقونة الوصفة في بوابة المواطن إلى "متاحة"، مما يعطي انطباعاً بالتكامل التقني العالي.

تضمن هذه المعمارية أن يظل النظام متفاعلاً وحياً، مما يرفع من ثقة المستخدمين في دقة المعلومات المقدمة عبر المنصة الوطنية.
